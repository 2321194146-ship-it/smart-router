# Smart Router 100% 验收与执行方案

## 目标定义

“100%”指本次发布范围内的目标全部有实现、有测试、有证据、有边界说明；不把未授权的真实生产流量、第三方配额或商业化能力伪装成代码完成。

发布范围：

- 后端统一请求链路：协议适配、任务分析、智能决策、预算/能力约束、Provider 执行、Fallback、持久化、Finalize、审计。
- 三协议兼容：Chat Completions、Responses、Anthropic Messages；包含流式、取消、首内容前回退和原生 Anthropic 透传。
- 生产安全：鉴权、回环管理面、请求体上限、限流、并发闸门、流式空闲/总时限、密钥不入库。
- 本地运维前端：Dashboard 状态查看、Kill Switch、恢复 Shadow；不宣称公网用户前端。
- 交付证据：全量测试、语法/格式检查、源文件哈希、发布范围和提交一致性。

## 门禁

| 门禁 | 验收条件 | 失败处理 |
|---|---|---|
| G0 需求边界 | 本文范围和未实现项明确 | 先修正文档，不进入发布 |
| G1 后端集成 | 请求从入口到 Provider、Fallback、Finalize 可追踪 | 补集成测试 |
| G2 协议契约 | 三协议非流式/流式、原生 Anthropic、取消行为通过 | 修 adapter 或执行引擎 |
| G3 安全 | 无硬编码密钥；非 loopback 鉴权；管理面 Token；输入限制 | 按 P0 处理 |
| G4 可靠性 | SQLite 恢复、幂等 Finalize、并发事务、流式时限通过 | 增加故障注入测试 |
| G5 前端 | Dashboard 本地可访问；CSP；Token 不落盘；Kill/Resume 可操作 | 修前端或路由保护 |
| G6 交付 | `npm test` 全绿；发布证据门禁全绿；提交范围清晰 | 禁止宣称发布完成 |
| G7 独立验收 | 独立审查员无 P0/P1；P2 有明确后续项 | 修复后重新跑 G0-G7 |

## 执行循环

1. 先跑 G0-G6，保存结果与提交号。
2. 独立验收员只读审查，禁止由实现者自我判定通过。
3. 按严重级别修复：P0 立即阻断；P1 必须修复；P2 可带明确后续计划发布。
4. 修复后重新运行受影响门禁，并再次独立验收。
5. 只有 G0-G7 全部满足，才标记为“本次发布范围 100% 达标”。

## 明确不在本次 100% 范围

- 公网用户产品前端、用户注册/登录、RBAC、租户系统。
- 账单、支付、商业化和云端多实例控制面。
- 未经老板确认的真实外部 Provider 生产流量或收费调用。

这些属于下一阶段产品化目标，不影响本次后端核心发布候选，但不能从最终报告中省略。
